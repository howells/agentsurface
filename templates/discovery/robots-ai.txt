# robots.txt - AI crawler policy
#
# Publish this content as /robots.txt. RFC 9309 defines /robots.txt as the only
# location crawlers read; a separate robots-ai.txt is not a standard discovery
# mechanism, so treat any extra file as a non-standard convention.
#
# Spec: https://www.rfc-editor.org/rfc/rfc9309.html
# Content Signals: https://contentsignals.org
# AI crawler documentation:
#   - OpenAI crawlers (GPTBot, OAI-SearchBot, ChatGPT-User, OAI-AdsBot): https://developers.openai.com/api/docs/bots
#   - Anthropic crawlers (ClaudeBot, Claude-SearchBot, Claude-User): https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler
#   - PerplexityBot: https://www.perplexity.ai/bot
#   - Google-Extended: https://developers.google.com/crawling/docs/crawlers-fetchers/overview-google-crawlers
#   - CCBot (Common Crawl): https://commoncrawl.org/ccbot
#   - Bytespider (ByteDance): https://www.bytedance.com
#
# DEFAULT POSTURE: allow search and retrieval bots, block model-training crawlers.
# This is the recommended starting point - it keeps your docs discoverable and
# citable in AI answers without donating them to training corpora. One trade-off:
# Google-Extended is a product token that also controls whether Google may use your
# content for Gemini grounding, not only training, so blocking it can reduce how
# Gemini products cite you. Search ranking is unaffected. Decide that line separately
# if Gemini visibility matters to you. If your project
# wants training visibility instead, see "TRAINING-VISIBLE ALTERNATIVE" below.
#
# Customize USER-AGENT lines and DISALLOW/ALLOW rules for your project.

# ---------------------------------------------------------------------------
# Content-Signal: state the content-use policy before any per-bot directives.
# Content Signals are a machine-readable statement of intent that sits alongside
# robots.txt rules. Declare them first so crawlers that honour the convention see
# your policy even if they ignore individual user-agent blocks.
#   search - may index for search results
#   ai-input - may retrieve at inference time to ground an answer
#   ai-train - may be used as model training data
#
# These three map directly onto how Cloudflare classifies AI bot traffic:
# Search (indexes content to answer questions later), Agent (acts in real time
# on a person's behalf - chat fetch bots, browser-use agents), and Training
# (crawls to train or fine-tune a model). Search and agent bots share the default
# group below; training bots get their own groups after it.
# ---------------------------------------------------------------------------
# One group for the default policy and the bots that follow it. A crawler obeys only
# the most specific group that names it and ignores `*` when it has its own group
# (RFC 9309, section 2.2.1), so a named bot given a short group of its own would lose
# every Disallow below. Consecutive User-agent lines share the rules that follow, which
# keeps the search bots and the user-initiated fetchers on the full list.
User-agent: *
# Search bots (real-time search indexing)
User-agent: OAI-SearchBot
User-agent: Claude-SearchBot
User-agent: PerplexityBot
# User-agent bots (fetching on behalf of a person)
User-agent: ChatGPT-User
User-agent: Claude-User
Content-Signal: search=yes, ai-input=yes, ai-train=no
Disallow: /admin/
Disallow: /private/
Disallow: /secrets/
Disallow: /.env
Disallow: /*.sql$
Disallow: /*.pem$
Allow: /llms.txt
Allow: /llms-full.txt
Allow: /robots.txt
Allow: /sitemap.xml
Allow: /AGENTS.md
Allow: /openapi.json
Allow: /.well-known/

# OpenAI also lists OAI-AdsBot, which checks pages submitted for ads. It is not a
# training or search crawler; add an explicit group for it if you want a policy.

# Training bots (model training data collection) - blocked by default
User-agent: GPTBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: Google-Extended
Disallow: /

User-agent: Meta-ExternalAgent
Disallow: /

User-agent: CCBot
Disallow: /
