## Summary

CLAUDE.md is a thin overlay on top of AGENTS.md for Claude Code-specific behavior only: skill triggers, tool allow/denylisting, permission mode, and session-level context hints. If Claude Code should behave differently from Cursor or Copilot, document it here - never repeat AGENTS.md content, reference it instead.

By default, Claude Code reads `CLAUDE.md` files only when one exists in the working directory or above it; if none exists, it reads `AGENTS.md` directly. **If both files exist, only `CLAUDE.md` loads - `AGENTS.md` is skipped entirely** unless the `CLAUDE.md` imports it with a literal `@AGENTS.md` line. See [Claude Code's memory docs](https://code.claude.com/docs/en/memory) for the full resolution order and the setting that changes it.

- **Skill triggers**: which skills to auto-invoke for this codebase
- **Tool allow/deny**: Claude-specific tool restrictions
- **Permission mode**: default mode and per-task overrides
- **Session hints**: context engineering for long-running sessions
- **Avoid**: repeating AGENTS.md, general conventions, project overview, model routing, or memory configuration (those belong to agent-building guidance, not to a repository context file)

CLAUDE.md is a thin overlay on top of AGENTS.md. It defines Claude Code-specific behavior only: skill triggers, tool boundaries, permission mode, session-level hints. If Claude Code should behave differently from Cursor or Copilot, document it here.

## When to Use CLAUDE.md

- Specific Claude skills should be triggered for this codebase
- Claude-specific tools (like `/review`) should be allowed or forbidden
- Permission mode differs from the account default
- Session-level hints apply to this codebase (for example, how to load per-package AGENTS.md in a monorepo)
- Your repository also has an `AGENTS.md` and you want Claude Code to read both - add a literal `@AGENTS.md` import (see below)

## When NOT to Use CLAUDE.md

- Documenting general project conventions (use AGENTS.md instead)
- Repeating commands already in AGENTS.md (reference instead)
- Listing coding standards or tech stack (link to AGENTS.md)
- Model selection or memory configuration - those are agent-building decisions, not repository context; keep this file scoped to what an agent needs to work safely in this repo

## Structure

### 1. Reference (or import) AGENTS.md

If your repository has both files and you want Claude Code to read `AGENTS.md` too, import it explicitly - a plain-English pointer like "See AGENTS.md" does not load the file, it only works if Claude decides to go read it:

```markdown
# CLAUDE.md

@AGENTS.md

## Claude Code

This file adds Claude Code-specific guidance only.
```

If you don't need `AGENTS.md` loaded automatically (for example, this repo has no `AGENTS.md`, or you deliberately want Claude Code's instructions to differ), skip the import and just state the relationship in prose.

### 2. Allowed Tools

```markdown
## Tools

Always allowed:

- Read, Bash, Git
- File creation and editing
- Tool use (any MCP server configured for the project, e.g. `.claude/mcp.json`)

Ask first:

- Database migrations (pnpm db:migrate)
- External API calls (e.g., curl to production)

Never allowed:

- Production deployments
- Credential rotation
- Branch/tag deletion
```

If AGENTS.md boundaries suffice, omit this section.

### 3. Claude Skills

Reference skills that should be auto-triggered for this codebase:

```markdown
## Skills

Auto-trigger these skills when relevant:

- /review - for pull request analysis
- /security-review - for auth/crypto changes

Disable:

- /schedule - not useful for this codebase
```

See https://code.claude.com/docs/en/skills for the skill reference.

### 4. Permission Mode

If the default permission mode should differ for this codebase:

```markdown
## Permissions

Default: plan (explore before editing)

Use bypassPermissions for:

- Automated refactoring tasks
- Lint fixes and formatting

Use dontAsk for:

- Code exploration (reading, grepping)
- Draft PR creation
```

See [Claude Code's permission modes](https://code.claude.com/docs/en/permission-modes) for the current mode list and what each one auto-approves.

### 5. Session Hints

Long-running sessions need context engineering:

```markdown
## Session Hints

- Break complex tasks into multiple sessions to avoid context bloat
- Use /compact at task end to compact conversation history
- For monorepo work, note which package's AGENTS.md applies before editing
```

### A note on memory

CLAUDE.md is instructions you write. Claude Code also maintains **auto memory** - notes Claude writes itself from your corrections, loaded automatically alongside CLAUDE.md - and `.claude/rules/`, a directory for splitting instructions into topic-scoped files (optionally scoped to a glob via `paths` frontmatter) instead of one long CLAUDE.md. Neither belongs inside CLAUDE.md itself; mention them here only if this repository relies on one and a contributor needs to know that. See [Claude Code's memory docs](https://code.claude.com/docs/en/memory) for how both work.

## Example: Simple Override

```markdown
# CLAUDE.md

@AGENTS.md

## Skills

Auto-trigger:

- /review for PR analysis
- /security-review for auth changes

## Permissions

Default: plan

Use dontAsk for: reading files, running tests, git operations.
```

This is minimal - no duplication with AGENTS.md.

## Do's and Don'ts

**Do:**

- Reference AGENTS.md instead of repeating it (import it with `@AGENTS.md` if you need Claude Code to load it automatically)
- Document Claude-specific decisions (permission mode, skills, tool boundaries)
- Keep it concise - target under 200 lines

**Don't:**

- Duplicate AGENTS.md content
- Explain general project conventions here (AGENTS.md)
- Over-specify behavior (let Claude Code use its judgment)
- Fold in model routing or memory configuration - that belongs to agent-building guidance, not a repository context file

## File Placement

CLAUDE.md lives at project root, same level as AGENTS.md:

```
.
├── AGENTS.md
├── CLAUDE.md
├── CONTRIBUTING.md
└── src/
```

For monorepos, an optional CLAUDE.md at package level (packages/api/CLAUDE.md) adds package-specific Claude hints. See [Monorepos](/docs/context-files/monorepos) for per-tool precedence.
