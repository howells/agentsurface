## Evaluation and Observability

Keep this category AI-specific. General monitoring tools are only relevant as trace backends when paired with GenAI instrumentation.

One selection signal is cheap to check and easy to overlook: whether your agent framework already ships an exporter for the backend. Framework-native exporters mean tracing is configuration rather than instrumentation work, and the list has widened well past the original three — Mastra, for one, ships exporters for Arize, Arthur, Braintrust, Datadog, Laminar, Langfuse, LangSmith, PostHog, and Sentry alongside plain OpenTelemetry. Check your framework's exporter list before you shortlist on features alone.

## Public Readiness Scanners

Public scanners answer a narrower question than a repository audit: what can an outside agent observe from the deployed site right now? Use them as smoke tests for crawl access, machine-readable content, discovery documents, public APIs, and callable surfaces. They cannot see an unpublished contract, an authenticated flow they cannot enter, or the source-level reason a check failed.

[Is Agentic](https://is-agentic.com/) is a Vercel service powered by Ora. Its Essential checks share an 80-point pool, Recommended checks share 20 points, and emerging signals can add up to five bonus points. Inapplicable surfaces are excluded; API, OAuth, MCP, GraphQL, and MCP Apps checks activate only when detected. The report timestamp and individual evidence matter more than the headline score because both the target and methodology can change.

Its public integration surfaces are deliberately read-only:

- `GET https://is-agentic.com/api/v1/report?url=...` retrieves the latest completed public report but does not start a scan.
- `npx is-agentic <domain> --json` returns a stored report or starts a scan when none exists.
- `https://is-agentic.com/mcp` exposes report, methodology, and developer-documentation tools over remote MCP.
- `npx skills add vercel-labs/is-agentic` installs its agent skill.

Only submit public URLs. Do not use an external scanner for private, authenticated, pre-release, or confidential environments merely to obtain a score. Pair the observed report with a [Surface audit](/docs/scoring), then trace failed signals back to code and deployment configuration.

## Ora / orank scans

[Ora](https://ora.ai/) provides a public score and actionable findings across discovery, access, usability, and payments. Retrieve the cached result with `GET https://ora.ai/api/score/agentsurface.dev`, or request a scan with `POST https://ora.ai/api/scan` and JSON body `{"url":"agentsurface.dev"}`. See its [API reference](https://ora.ai/api/openapi.json) for caching and rate limits.

Treat each finding as evidence to investigate. A public documentation API benefits from OpenAPI and recoverable JSON errors; it does not need an OAuth authorization server when no protected resources exist. Wikipedia and Wikidata presence depend on independent evidence and eligibility, not configuration. Record the scan date and deployed version before comparing scores.

Use [Evaluating Product Journeys](/docs/scoring/product-journeys) to interpret external findings in terms of a real task, source ownership, applicability, and verified outcomes.

## Cloudflare Agent Readiness

[Cloudflare's checker](https://isitagentready.com/) covers discovery, content, bot access control, API/auth/tool metadata, and commerce. It exposes a [skill index](https://isitagentready.com/.well-known/agent-skills/index.json), a remote MCP server at `https://isitagentready.com/mcp`, and a scan API:

```sh
curl https://isitagentready.com/api/scan \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://example.com"}'
```

The comparison verified on **10 September 2026** found 22 available checks; the website's default selection excludes A2A and AP2. Commerce is excluded from the displayed overall percentage, and neutral results do not count in its denominator. The API also returns a separate readiness level. Record the selected checks and scan time when comparing results.

Its useful differences from [Ora's published catalog](https://ora.ai/api/checks) are:

- **DNS-AID:** an additional DNS discovery check, absent from Ora contract 1.24.0's 125 checks. See [DNS Discovery](/docs/discovery/dns-discovery) for applicability and verification.
- **Content Signals:** a separate check from crawler rules. Ora already accepts Content Signals within its crawler-policy check. Keep access and content use separate in your implementation even when a scanner combines their scores.
- **Discovery routes:** the catalog probe also tries DNS TXT and SRV records. A broader set of probes does not imply a new product requirement.

Is Agentic uses Ora's checks, so it provides another interpretation of that evidence rather than an independent checklist. Most Cloudflare capabilities overlap Ora, with different acceptance criteria and weights. Use each report to investigate actual client failures; a scanner's preferred path or older API name is not a substitute for the current protocol specification.
