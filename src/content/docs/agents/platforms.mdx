## Summary

Treat Claude, OpenAI, and Gemini as platforms: all three ship a hosted execution surface, and Claude and OpenAI add MCP connectors for reaching external tools plus a shared cross-vendor Agent Skills mechanism. The common failure is scaffolding against last quarter's shape - a retired API, a superseded model ID, or a renamed parameter.

Anthropic docs live at `platform.claude.com`; Claude Code docs live at `code.claude.com`. OpenAI docs live at `developers.openai.com` (the old `platform.openai.com` paths redirect there). Gemini docs live at `ai.google.dev` and `blog.google`.

## Anthropic

| Surface                        | Use when                                                              | Notes                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------ | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Managed Agents          | Anthropic should run the autonomous agent harness                     | Public beta since 2026-04-08. Sessions, environments, SSE events, cron deployments, MCP tunnels; a session that mounts a GitHub repo now auto-discovers skills in that repo's `.claude/skills` (since 2026-08-07). Dynamic workflows (beta, 2026-10-09: `multiagent_20261001` with workflows enabled, `workflow_run.*` events) and OpenTelemetry export (beta, 2026-10-14) are the newest additions. |
| Claude Code / Claude Agent SDK | Coding-agent work: repo inspection, editing, tests, incident response | Same product; `@anthropic-ai/claude-agent-sdk` (npm), `claude-agent-sdk` (PyPI).                                                                                                                                                                                                                                                                                                                     |
| Messages API + MCP connector   | A request needs remote MCP tool calls without a managed session       | Tool-call support only, not the full MCP primitive set. Beta headers `inline-tools-2026-09-15` and `mcp-client-2026-09-15` (2026-09-22) let a mid-conversation system message add or redefine tools and pin a connected server's fetched tool list across requests, so a catalog change no longer invalidates the prompt cache.                                                                      |
| Agent Skills                   | Reusable procedures, scripts, and domain workflows                    | Cross-vendor open standard (`agentskills.io`), not Claude-only. The Skills API (`/v1/skills`) left beta 2026-08-19; no beta header required.                                                                                                                                                                                                                                                         |
| Computer use / browser use     | The agent should act on a real UI, not just call an API               | `computer_toolset_20260801` and `browser_toolset_20260801` left beta 2026-08-19, available across the current Claude model line. The earlier `computer_20251124` tool errors on Opus 5.5 and later on the Claude API and Google Cloud (it still works on Amazon Bedrock) - migrate to the toolset ID.                                                                                                |
| Built-in tools                 | Web search, web fetch, code execution, tool search, memory tool       | GA since 2026-02-17. Compaction on demand (beta header `compact-2026-09-04`, shipped 2026-09-14) lets a caller compact a conversation into a signed summary block on its own schedule and resend that block in place of the summarized messages.                                                                                                                                                     |

Choose **Managed Agents** when sessions, credential vaulting, webhooks, or scheduled runs should be Anthropic-operated rather than embedded in your own app server. Choose **Claude Code / Agent SDK** when a human or service needs the coding harness directly. Choose the **MCP connector** when a single Messages API request just needs remote tool calls. Choose a **custom MCP server** when Claude, OpenAI, and other clients all need the same vendor-neutral contract.

Current model IDs as of 2026-10-29: **Opus 5.5** (`claude-opus-5-5`) is the recommended default for agent and coding work; **Fable 5.1** (`claude-fable-5-1`) is the flagship for deep reasoning and long tasks; **Sonnet 5.5** (`claude-sonnet-5-5`, 2026-09-28) is the balanced mid tier; **Haiku 5.5** (`claude-haiku-5-5`, 2026-10-07) is the low-latency option. Current pinned IDs are dateless - do not append a date suffix. See [Model Reference](/docs/reference-links/models) for the full allowlist.

Anthropic API version `2026-10-21` is the default for the new major client SDKs. It removes `temperature`, `top_p`, and `top_k` (a request that sends them returns a 400). The Claude Agent SDK is versioned separately.

## OpenAI

| Surface                       | Use when                                                                  | Notes                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Responses API + Conversations | The base for all new OpenAI agent work                                    | The Assistants API was sunset 2026-08-26 - every call to it now errors, no transition window. Threads/Runs map to Conversations/Responses; there is no automated migration tool. Async tool calls and mid-turn steering (2026-09-03) let the model keep working while a tool runs and let a caller send corrections into an in-progress response over WebSockets. |
| Agents API (beta)             | OpenAI should run the agent harness, not your own app server              | Public beta since 2026-09-10: a managed Codex harness with OpenAI handling session orchestration, context compaction, and recovery; durable sessions, progress streaming, custom tools, MCP servers, and a choice of OpenAI-hosted or customer-provided sandboxes.                                                                                                |
| OpenAI Agents SDK             | Embedding the agent loop in an app or service                             | `@openai/agents` (npm), `openai-agents` / `agents` (PyPI). Agents, handoffs, guardrails, sessions, tracing.                                                                                                                                                                                                                                                       |
| Hosted Shell tool             | The agent should run real shell commands in an isolated container         | Fresh-per-request or reused-across-turns containers; common runtimes preinstalled.                                                                                                                                                                                                                                                                                |
| Agent Skills in the API       | Reusable procedures loaded into the Shell environment on demand           | Same open `SKILL.md` standard as Anthropic and other adopters.                                                                                                                                                                                                                                                                                                    |
| Server-side compaction        | A run outgrows the context window                                         | Summarizes prior turns server-side; not a memory system or an audit log.                                                                                                                                                                                                                                                                                          |
| Built-in hosted tools         | Web search, file search, code interpreter, computer use, image generation | Hosted by OpenAI and billed as tool use.                                                                                                                                                                                                                                                                                                                          |

Any code still targeting the Assistants API belongs on the migration guide below; build new work directly on Responses + Conversations. Choose the **Agents API** when the harness itself - orchestration, compaction, recovery - should be Codex-operated rather than assembled from the SDK; choose the **Agents SDK** when the app needs to own that loop directly.

Current model IDs as of 2026-10-29: **GPT-6 Astra** (`gpt-6-astra`, flagship), **GPT-6.1 Sol** (`gpt-6.1-sol`), **GPT-6.1 Terra** (`gpt-6.1-terra`, balanced default, 2026-10-26), **GPT-6 Luna** (`gpt-6-luna`, fastest/cheapest). See [Model Reference](/docs/reference-links/models).

## Gemini

Google's managed-agent surface on the Gemini API, expanded 2026-07-28:

| Surface           | Use when                                                | Notes                                                                                                                                                                                                   |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Environment hooks | Custom checks should run around every tool call         | A `.agents/hooks.json` script runs on `pre_tool_execution` and `post_tool_execution` inside the sandbox - block, lint, or audit a tool call before or after it executes.                                |
| Token budgets     | A run must not exceed a known cost                      | `max_total_tokens` caps input, output, and thinking tokens combined; the task pauses safely at the limit and returns `status: "incomplete"` with environment state preserved, rather than erroring out. |
| Cron scheduling   | An agent should run unattended on a schedule            | Triggers bind an agent, environment, prompt, and cron schedule into a persistent resource that fires without manual intervention; sandboxes persist across scheduled runs.                              |
| Environments API  | Sandbox sessions need programmatic lifecycle management | List, inspect, and delete environments directly instead of waiting on the default 7-day timeout.                                                                                                        |

Gemini 3.8 Flash (`gemini-3.8-flash`) is the Flash model Google's catalogue now recommends for new work, with Gemini 3.5 Flash-Lite for cost-sensitive runs; check managed-agent endpoint support before changing a deployment pin from 3.7 Flash. The hook, budget, scheduling, and Environments API details above come from Google's July 2026 announcement, and no dated managed-agent API reference was found on 2026-10-29 to re-confirm them. Google's published docs do not describe an Agent Skills mechanism or an MCP connector for the managed-agent path, so confirm both before relying on them. Treat this as a narrower surface than Claude Managed Agents or the OpenAI Agents API, and treat it as the right fit for scheduled, budget-bounded background agents on Gemini rather than a general replacement for the other two.

## MCP Notes

None of the three platforms support the full MCP primitive set through every path. State which path is in use, and do not assume support for resources, prompts, roots, sampling, elicitation, or tasks unless the specific surface documents it:

- Claude Code uses local stdio and remote Streamable HTTP MCP servers via `.mcp.json`, and can itself act as an MCP server with `claude mcp serve`.
- The Claude Messages API MCP connector supports `mcp_toolset` with `defer_loading` for large catalogs and OAuth bearer tokens, but only MCP tool calls.
- OpenAI can call remote MCP servers as hosted tools from a Responses request, plus OpenAI-maintained connectors for common third-party systems; private servers reach it through a secure tunnel.

See [MCP Protocol](/docs/protocols/mcp) and [MCP Auth Model](/docs/authentication/mcp-auth-model) for the protocol-level detail these platforms build on.

## Security Guidance

The same rules apply across all three platforms:

- Treat model-visible tool descriptions, MCP annotations, connector metadata, and Skill content as advisory input, never a trust boundary.
- Enforce authorization, tenant identity, and scope checks in trusted server code - not in the prompt.
- Gate destructive, external, authenticated, production, browser, and sandbox/container tools with confirmation policies (see [Prompts and Configuration](/docs/agents/prompts-and-configuration) and [Guardrails](/docs/agents/guardrails)).
- Keep production credentials out of prompts, Skill text, and sandbox/container environments; broker privileged actions through a server-side tool the sandbox cannot bypass.
- Log agent/session identity, user or tenant context, tool calls, approvals, and outcomes.
