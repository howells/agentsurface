Agent Retrieval is how an agent finds and uses knowledge for its own work - vector search, embeddings, and retrieval-augmented generation. It is part of the Build agents half of the site: a condensed, current-best-practice reference for teams building an agent's retrieval stack. The product-facing side - making your own product's data retrievable by other agents - is covered in [Retrievability](/docs/retrievability).

## Summary

The durable pattern is stable even as vendors and benchmarks move fast: combine sparse keyword retrieval, dense semantic retrieval, metadata filters, reranking, and evaluation. Dense-only vector search is a fine prototype baseline and rarely enough for a production agent that needs exact identifiers, permissions, and citations.

- **Hybrid beats dense-only** for mixed corpora - combine keyword and dense signals unless an eval proves one is enough.
- **Chunking is product logic** - preserve source, section, and version metadata; do not index anonymous text blobs.
- **Reranking improves precision** - retrieve broad, rerank narrow.
- **Graphs are a maintenance commitment** - add one only when relationships are explicit and queried often.
- **Evaluate retrieval, not just generation** - recall, ranking quality, faithfulness, latency, and cost all need gates.

This corner of the ecosystem moves fast: embedding models, vector database pricing, and framework recommendations change over months.
