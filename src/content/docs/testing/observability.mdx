## Summary

The ability to inspect agent execution: which tools called, in order, with what arguments, and what they returned. Traces are source of truth for debugging. OpenTelemetry GenAI semantic conventions standardize instrumentation across providers (Anthropic, OpenAI, Google), but the current conventions are marked Development. Key spans: agent invocation (`invoke_agent`), model calls (`chat {model}`, with model and token usage), tool execution (`execute_tool {tool}`), and errors (`error.type`). Message and tool content is opt-in. Export to Langfuse, Arize Phoenix, Datadog, or Grafana Cloud for visualization and alerting.

```
invoke_agent my-agent
├── chat claude-opus-5-5          (model call: tokens, latency)
├── execute_tool search_docs      (tool name, call id, duration, status)
├── execute_tool read_file
└── chat claude-opus-5-5
```

---

Agent observability is the ability to inspect what happened: which tools were called, in what order, with what arguments, and what did they return? Traces are the source of truth for debugging. Use OpenTelemetry GenAI semantic conventions to standardize instrumentation across providers, but treat the conventions as a moving target: they remain Development (experimental) status with nothing stable, and as of mid-2026 they are unversioned, so record which convention snapshot you instrumented against and expect attribute names to shift.

## OpenTelemetry GenAI semantic conventions

The GenAI conventions define standard attributes for LLM and agent spans. Their status is Development (experimental) - nothing in the GenAI set is stable or stabilizing yet.

As of semantic-conventions v1.42.0 (2026-06-12), all `gen_ai.*` and `mcp.*` conventions moved out of the mainline spec into a dedicated repository, [open-telemetry/semantic-conventions-genai](https://github.com/open-telemetry/semantic-conventions-genai). The old opentelemetry.io gen-ai pages (`https://opentelemetry.io/docs/specs/semconv/gen-ai/`) are now redirect stubs. The new repository had no tagged releases at the last check (2026-10-29), so the GenAI conventions are currently unversioned - you cannot pin an emitted convention version; pin to a commit or snapshot instead. Mainline semantic-conventions v1.43.0 (2026-07-03) ships with no gen-ai content.

### Model call span

A model call is an inference span. Its operation name is `chat` (or another well-known value such as `generate_content` or `text_completion`), and the span name is `{gen_ai.operation.name} {gen_ai.request.model}`. Start it with `startActiveSpan` so any span created inside the callback becomes its child, and read token usage from the response rather than guessing it up front.

```typescript
import { trace } from "@opentelemetry/api";

const tracer = trace.getTracer("agent");

async function callModel(prompt: string) {
  return tracer.startActiveSpan(
    "chat claude-opus-5-5",
    {
      attributes: {
        "gen_ai.operation.name": "chat",
        "gen_ai.provider.name": "anthropic",
        "gen_ai.request.model": "claude-opus-5-5",
        "gen_ai.request.max_tokens": 4096,
      },
    },
    async (span) => {
      try {
        const response = await callClaude({
          model: "claude-opus-5-5",
          max_tokens: 4096,
          messages: [{ role: "user", content: prompt }],
        });

        span.setAttributes({
          "gen_ai.usage.input_tokens": response.usage.input_tokens,
          "gen_ai.usage.output_tokens": response.usage.output_tokens,
        });

        // Opt-in content, structured as role + parts. Only record it when your
        // data-handling rules allow; otherwise leave it out.
        // span.setAttribute("gen_ai.input.messages", JSON.stringify([
        //   { role: "user", parts: [{ type: "text", content: prompt }] },
        // ]));

        return response;
      } catch (err) {
        span.setAttribute("error.type", err instanceof Error ? err.name : "unknown");
        throw err;
      } finally {
        span.end();
      }
    },
  );
}
```

### Agent and tool spans

An agent invocation is a separate span from a model call. Its name is `invoke_agent {gen_ai.agent.name}` (or `invoke_agent` when the name is not available), with `gen_ai.operation.name` set to `invoke_agent`. Tool execution uses `gen_ai.operation.name = execute_tool` and the span name `execute_tool {gen_ai.tool.name}`. Spans started while another span is active become its children; OpenTelemetry JS parenting comes from the active context, not from a `parent` option.

```typescript
async function runAgentWithTools(prompt: string) {
  return tracer.startActiveSpan(
    "invoke_agent my-agent",
    {
      attributes: {
        "gen_ai.operation.name": "invoke_agent",
        "gen_ai.agent.name": "my-agent",
        "gen_ai.provider.name": "anthropic",
      },
    },
    async (agentSpan) => {
      try {
        const response = await callClaude({ messages: [{ role: "user", content: prompt }] });

        for (const toolCall of response.tool_calls) {
          // Started while agentSpan is active, so it is a child automatically
          await tracer.startActiveSpan(
            `execute_tool ${toolCall.name}`,
            {
              attributes: {
                "gen_ai.operation.name": "execute_tool",
                "gen_ai.tool.name": toolCall.name,
                "gen_ai.tool.call.id": toolCall.id,
              },
            },
            async (toolSpan) => {
              try {
                const result = await executeTool(toolCall);
                // Opt-in content: arguments and results may hold sensitive data
                toolSpan.setAttributes({
                  "gen_ai.tool.call.arguments": JSON.stringify(toolCall.arguments),
                  "gen_ai.tool.call.result": JSON.stringify(result),
                });
              } finally {
                toolSpan.end();
              }
            },
          );
        }

        return response;
      } finally {
        agentSpan.end();
      }
    },
  );
}
```

### Attribute reference

Requirement levels differ by attribute and by span type, so do not read this as a list that every span must carry. Check the [client inference](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/client-inference.md), [agent](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md) and tool-execution documents for the level of each.

**Model call span:**

- `gen_ai.operation.name` - required, e.g. "chat"
- `gen_ai.provider.name` - required, e.g. "anthropic", "openai", "google"
- `gen_ai.request.model` - conditionally required when available, e.g. "claude-opus-5-5"
- `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` - recommended
- `gen_ai.request.temperature`, `gen_ai.request.max_tokens` - optional request parameters; record temperature only for models that accept one
- `gen_ai.response.model`, `error.type` - when available, and when the call fails
- `gen_ai.data_source.id` - the corpus ID if RAG is used

**Opt-in content** (off unless you choose to capture it, subject to your sensitive-data rules):

- `gen_ai.input.messages` / `gen_ai.output.messages` - structured messages, each with a `role` and `parts` (for example `{ "type": "text", "content": "..." }`), not plain `{role, content}` objects or hashes
- `gen_ai.system_instructions` - structured instruction content, not a hash or a summary; use `gen_ai.system_instructions_ref` to point to content stored elsewhere, and omit it when it contains secrets

**Tool execution span:**

- `gen_ai.tool.name` - required
- `gen_ai.tool.call.id` - conditionally required
- `gen_ai.tool.call.arguments` / `gen_ai.tool.call.result` - opt-in

**Agent span:** `gen_ai.agent.name`, `gen_ai.agent.id`, `gen_ai.agent.version`, with operations that include creating and invoking an agent.

Custom attributes such as `task.id` or `tool.output_tokens` are fine, but they are your own names, not part of the conventions.

### MCP spans

The same repository defines MCP client and server spans. They carry `mcp.method.name` (for example `tools/call`), conditionally `gen_ai.tool.name` or `mcp.resource.uri`, and a recommended `mcp.protocol.version`, with span names of the form `{mcp.method.name} {target}`. Use them when you instrument an MCP server or client; see [mcp.md](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/mcp.md) for the current definitions.

## Instrumentation libraries

### Traceloop SDK

Auto-instruments supported LLM SDK calls (check the README for the current list). The Node package is `@traceloop/node-server-sdk` (0.27.0 at the last check); the `@traceloop/sdk` name does not exist on npm. Initialize it before importing the LLM modules you want instrumented:

```typescript
import * as traceloop from "@traceloop/node-server-sdk";

traceloop.initialize({
  appName: "my-agent",
  apiKey: process.env.TRACELOOP_API_KEY,
});

// Import LLM SDKs after initialize() so they can be instrumented
const { default: Anthropic } = await import("@anthropic-ai/sdk");
const client = new Anthropic();
const response = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Hello" }],
});
// Traceloop sends a span for the call; check which attribute names your version emits
```

### OpenLLMetry

Python-first auto-instrumentation:

```bash
pip install opentelemetry-instrumentation-openai
from opentelemetry.instrumentation.openai import OpenAIInstrumentor
OpenAIInstrumentor().instrument()
```

For TypeScript, use Traceloop or manual instrumentation.

### Manual instrumentation

For full control, use `@opentelemetry/api`:

```typescript
import { context, trace } from "@opentelemetry/api";

const tracer = trace.getTracer("agent");

async function evaluateAgent(task: string) {
  const span = tracer.startSpan("agent.evaluation", {
    attributes: {
      // Custom attributes (not part of the GenAI conventions)
      "task.id": task,
      "task.difficulty": "medium",
    },
  });

  try {
    const agent = new MyAgent();
    const result = await agent.run(task);

    span.setAttributes({
      "task.completed": result.success,
      "task.steps": result.steps.length,
      "task.tokens_used": result.tokensUsed,
    });

    return result;
  } finally {
    span.end();
  }
}
```

## Exporting traces

Traces must be exported to a backend for storage and querying. Use OTLP (OpenTelemetry Protocol). In the JavaScript SDK 2.x, span processors are passed when the provider is constructed, and the HTTP trace exporter needs the full signal path:

```typescript
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";
import { BatchSpanProcessor, NodeTracerProvider } from "@opentelemetry/sdk-trace-node";

const exporter = new OTLPTraceExporter({
  url: process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT || "http://localhost:4318/v1/traces",
  // Common endpoints:
  // http://localhost:4318/v1/traces - a local OpenTelemetry Collector
  // https://cloud.langfuse.com/api/public/otel/v1/traces - Langfuse Cloud (EU)
  // Phoenix: use @arizeai/phoenix-otel (see below)
});

const provider = new NodeTracerProvider({
  spanProcessors: [new BatchSpanProcessor(exporter)],
});
provider.register(); // also installs the context manager that makes span parenting work
```

Pin the SDK version you test against: the span-processor setup changed between 1.x and 2.x.

## Backends

### Langfuse

Managed SaaS backend with trace UI, eval API, cost tracking. For direct OTLP export, use your region's host and the `/api/public/otel/v1/traces` path with Basic authentication built from the project's public and secret keys:

```typescript
const auth = Buffer.from(
  `${process.env.LANGFUSE_PUBLIC_KEY}:${process.env.LANGFUSE_SECRET_KEY}`,
).toString("base64");

const exporter = new OTLPTraceExporter({
  url: "https://cloud.langfuse.com/api/public/otel/v1/traces", // EU; US: us.cloud.langfuse.com
  headers: {
    Authorization: `Basic ${auth}`,
    "x-langfuse-ingestion-version": "4", // real-time ingestion on the v4 data model
  },
});

// Traces appear in the Langfuse dashboard for your region
```

Langfuse's own SDKs have moved on: the JS/TS SDK is v6 (`@langfuse/otel`, 6.0.2 at the last check) and the Python SDK is v5. The old unscoped `langfuse` npm package describes itself as deprecated, so new code should start from the v6 packages.

Langfuse docs: https://langfuse.com/

### Arize Phoenix

Open-source, self-hostable OTEL backend. Deploy locally or on cloud.

```bash
# Run locally
docker run -p 6006:6006 arizephoenix/phoenix:latest

# Or cloud: https://app.phoenix.arize.com
```

The command above publishes port 6006 only; it does not open an OTLP receiver on 4318. Use Phoenix's own registration helper, which points the exporter at the Phoenix collector endpoint:

```typescript
import { register } from "@arizeai/phoenix-otel";

const provider = register({
  projectName: "my-agent",
  url: "http://localhost:6006", // normalized to the OTLP endpoint at /v1/traces
});
```

For Phoenix Cloud or a hosted instance, pass its URL and `apiKey`. Phoenix is separate from Arize's commercial platform; follow the [Phoenix TypeScript tracing setup](https://arize.com/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-tracing-ts) rather than a generic Arize hostname.

Phoenix docs: https://arize.com/phoenix

### Braintrust

Braintrust records traces for the code you wrap with its SDK, alongside eval results. Inside `Eval`, the task and scorers are traced; nested provider and tool calls appear when they go through `wrapAnthropic`/`wrapOpenAI` or a `traced` block. See [Braintrust Evals](/docs/testing/braintrust).

```typescript
import { Eval, initDataset } from "braintrust";

await Eval("my-agent", {
  data: initDataset({ project: "my-agent", dataset: "tasks" }),
  task: async (input) => {
    // Agent runs here; wrapped clients and traced() blocks show up as child spans
    return await agent.run(input);
  },
  scores: [scoreQuality],
});

// View traces in Braintrust UI alongside eval results
```

## Querying traces for debugging

Once traces are in a backend, query them by attributes:

```typescript
// Pseudocode for Langfuse query - not a real SDK call
const traces = await langfuse.traces.list({
  filter: {
    "attributes.gen_ai.provider.name": "anthropic",
    "attributes.gen_ai.usage.input_tokens": { gte: 1000 },
  },
});

// Find all tool calls to delete_user
const deleteSpans = traces.flatMap((t) =>
  t.spans.filter((s) => s.attributes["gen_ai.tool.name"] === "delete_user"),
);

console.log(`Found ${deleteSpans.length} delete_user calls in past 24h`);
```

## Sampling for cost control

At scale, sampling traces reduces storage and export costs. The SDK-side samplers do head sampling: the decision is made when the root span starts, before anyone knows whether the trace will fail.

```typescript
import {
  BatchSpanProcessor,
  NodeTracerProvider,
  ParentBasedSampler,
  TraceIdRatioBasedSampler,
} from "@opentelemetry/sdk-trace-node";

// Head sampling: keep 10% of new traces; child spans follow their parent's decision
const sampler = new ParentBasedSampler({
  root: new TraceIdRatioBasedSampler(0.1),
});

const provider = new NodeTracerProvider({
  sampler,
  spanProcessors: [new BatchSpanProcessor(exporter)],
});
```

Head sampling cannot promise to keep every error, because a future error is unknown at the first span. If you need all failed traces, export everything to an OpenTelemetry Collector and use tail sampling there (the Collector's tail sampling processor can keep traces by status, latency or attributes, and sample the rest). See [OpenTelemetry sampling](https://opentelemetry.io/docs/concepts/sampling/).

## Relationship to eval metrics

Traces provide raw data; metrics summarize traces.

- **Trace** - Full execution: agent called search_docs, got 5 results, called read_file on 2 of them, summarized output. (Detailed, expensive to store)
- **Metric** - pass@1=1, tool_f1=0.95, latency_p99=2.3s. (Summarized, cheap to store)

For production monitoring, store metrics. For debugging, query traces. Use `gen_ai` attributes in traces to join with eval metrics:

```
SELECT count(*) FROM traces WHERE
  attributes."gen_ai.provider.name" == "anthropic" AND
  attributes."gen_ai.usage.output_tokens" > 5000
GROUP BY attributes."gen_ai.request.model"
```
