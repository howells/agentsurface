## Editorial rules

Coverage is many-to-one: related checks share a card. It is not 125 separate homepage cards. Six additional cards cover broader product concerns beyond primary scanner mappings (such as authoritative availability, outcome verification, and monitoring).

“Adapted” means the underlying concern is covered, while the guide deliberately qualifies a scanner prescription. Examples include optional OAuth for public services, legitimate encyclopedia eligibility, genuine attestations, no arbitrary tool count, distinct ARD/AI Catalog schemas, client-specific NLWeb contracts, and server-enforced authority despite tool annotations. We do not claim that following every card mechanically reproduces a vendor score.

## Maintenance

The [machine-readable coverage record](research/homepage-coverage-2026-09-10.json) stores source retrieval evidence, per-definition fingerprints, check IDs, card IDs, reference routes, and editorial decisions. It is research provenance, not a homepage dependency or a new scoring system.

Run `node scripts/check-homepage-coverage.mjs` to check mapping integrity and documentation targets. Add `--live` to compare against the published catalog, including definition changes that keep the same ID or version. A live mismatch requires editorial review; the script does not silently bless new criteria. It deliberately does not run a network scan during builds. Recheck Is Agentic's methodology separately when refreshing the mapping.

## Adaptation notes

- **ard-catalog:** Use the current ARD schema supported by the consumer; do not equate file presence with a working capability.
- **ai-catalog-published:** AI Catalog has its own schema. Do not repeat the scanner claim that an ARD document always works unchanged.
- **ard-trust-manifest:** Publish only substantiated claims; validate issuer and subject rather than awarding trust for a field.
- **wikipedia-presence:** Earn independent coverage and check eligibility; no blanket recommendation to create an encyclopedia article.
- **bot-detection:** Choose access policy by intended traffic; a User-Agent string does not prove identity.
- **robots-ai-policy-quality:** Search, user retrieval, and training are distinct policy choices. Do not copy a blanket crawler allowlist.
- **agent-mode-view:** Provide an equivalent agent-readable representation where useful; the query parameter itself is not a universal requirement.
- **skills-sh-quality:** Publish useful focused skills; more repositories are not intrinsically better.
- **mcp-server-identity:** Declare identity and capabilities through the protocol revision the client actually supports; do not hardcode an obsolete handshake.
- **org-schema-completeness:** Include accurate, appropriate contact information; do not fabricate an address.
- **schema-type-breadth:** Use applicable types backed by real facts; do not invent ratings or reviews.
- **mcp-tool-listing:** Expose useful operations. No arbitrary minimum tool count or obligation to add writes.
- **oauth-support:** Use OAuth for delegated protected access when appropriate; public resources may be anonymous.
- **mcp-auth-mechanism:** Protect private capabilities; public read-only MCP need not invent OAuth.
- **mcp-oauth-metadata:** Publish capabilities supported by the actual authorization server and client; preserve required compatibility.
- **onboarding-friction:** Offer a usable supported onboarding path and test environment; a free tier is a product choice.
- **web-bot-auth-directory:** The sender or identity provider publishes keys; a receiver verifies requests. Publishing a directory does not authenticate inbound users.
- **ap2-support:** Signed mandates express authority; they do not replace settlement, checkout, or provider compatibility.
- **agent-auth-endpoints-reachable:** Verify the real advertised flow, not just non-404 OPTIONS responses.
- **nlweb-ask:** Use the pinned NLWeb implementation contract; a generic /ask route is not compatibility.
- **nlweb-streaming:** Verify actual framing and completion; the reference implementation uses a streaming option, not necessarily the scanner example shape.
- **mcp-tool-annotations:** Annotations are untrusted advisory hints; enforce authorization and approvals separately.
- **mcp-multi-surface-coverage:** Provide learning and action capabilities where useful; separate servers are not intrinsically required.
- **graphql-pagination-pattern:** Connection pagination is useful, not a GraphQL requirement; document the chosen contract.
- **agent-ua-markdown:** Optional representation optimization; prefer explicit content negotiation and preserve equivalent facts and correct caching.
- **ax-tree-injection-safe:** Preserve legitimate screen-reader content while isolating untrusted instructions; detection is not a security guarantee.
- **a2ui-support:** The scanner accepts several interactive UI approaches; use a supported host integration, not an assumed universal A2UI protocol.
- **mcp-view-domain:** Ensure the host can load the view; data and tool actions still require appropriate authorization.
- **mcp-view-csp:** Scope policies to actual host origins and integrations; do not grant every named host automatically.
- **agent-crawler-reachability:** Verify access from intended clients; do not grant trust or permission based on a claimed bot name.
