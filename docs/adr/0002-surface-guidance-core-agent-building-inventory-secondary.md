# Surface guidance is the core; agent building is a secondary inventory

Agent Surface has two parts. The core is the guide and the surface skill: making an existing product (website, app, API, CLI, MCP server) usable by agents, and testing that it works. The secondary part is the agent-building inventory: condensed, current best practice and a curated list of tools and platforms for teams building their own agents (frameworks, orchestration, memory, durable execution, browser and sandbox access, guardrails, agent retrieval). An earlier decision kept agent-internal architecture out entirely; we reversed it because the inventory is worth maintaining as a reference, but we keep it out of the core so the guide doesn't turn into a broad agent-building toolkit.

The consequences are that the docs navigation splits into two labelled parts, the homepage covers only the product side, and the surface skill's Guide, Audit and Scaffold routes stay product-side and framework-neutral. Inventory pages each give one short summary of current practice per topic, with no deep tutorials. Framework ecosystems such as Mastra's integration lists are used as sources for the inventory without being credited as the authority.
